E499 사전등록 — 메모리를 넣고도 접기가 이득인 영역을 찾는다

E498 은 decode 이득이 1.00x 로 사라짐을 보였다. 남은 질문은 '그럼 어디서 되나' 다.
(M,K,N) x 배열크기를 쓸어서 roofline max(compute, memory) 기준 실제 이득을 계산한다.

구조에서 예상되는 것:
  원천 (a) 'M<h 라 pass 길이가 준다' 는 E498 이 거의 닫았다 (16x16+L2 의 M=11~15 만).
  원천 (b) 'N 타일 수가 S 배 준다' 는 안 닫혔다. 조건은
     - N > cols  (타일이 여러 개여야 줄일 게 있다)
     - K <= h    (안 그러면 ceil(K/h) 가 커져 상쇄한다)
     - 총 바이트 <= L2  (아니면 DRAM 이 지배)
  즉 **얕은 K + 넓은 N + L2 상주** — 초기 CNN 층의 모양이다.

[예측]
  [1] 쓸어본 전 영역의 **최대 실제 이득이 2.5배 미만**. 메모리가 천장을 씌운다.
  [2] 이득 >= 1.2배 인 칸은 대부분 `K <= h` 이고 총 바이트가 L2 안이다.
  [3] **작은 배열이 유리하다** — 8x8 이 32x32 보다 이득 나는 칸이 많다.
      peak 은 rows^2 로 크는데 창은 rows 로만 크므로 (E498), 큰 배열일수록 닫힌다.
      이는 E491(면적)·E497(compute)의 '크면 좋다' 와 **정반대** 방향이다.

틀리면: [1] 이 틀리면(2.5배 넘는 칸이 있으면) 그 칸이 이 설계의 진짜 목표다.
        [3] 이 틀리면 배열 크기 권장이 다시 뒤집힌다.
