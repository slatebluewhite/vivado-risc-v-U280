E539 사전등록 — matmul_id 고갈 가설 (E538 트레이스에서 유도)

관측 (16x16 ms8, seq(0,3,0) 트레이스): phase3 출력이 2행 묶음으로 재정렬되고 2행이
소실. S=8(h=2) phase 는 total_rows=4 로 재발행하며 drain 26 사이클 -> 동시 진행
matmul ~9 > id 공간 5 (E518 산식이 floor>=4 게이트로 꺼져 있음).

예측:
[1] (하네스 acc 용량 #5 수정 후, RTL 그대로) 16x16 ms8 (0,3,0)/(3,3,0) 은 여전히
    실패한다 — 소실·재정렬은 id alias 소행이므로 (뱅크 굴러들어감만 사라진다).
[2] **잠재 버그**: 16x16 ms4 floor 4 에서도 h=4 shape 에 M=4, K=64(c=16 matmul)를
    주면 alias 가 난다 (in-flight ~= 28/4+1 = 8 > 5). 기존 ms4 검증이 못 본 이유는
    XTop 류가 M=16(재발행 16 사이클)이었기 때문. seq(2,0,0) M=4 K=64 로 확인.
[3] ss_n_sim 게이트 제거(산식을 need>5 인 모든 shapeshift 구성에 적용) 후 [1][2] 모두
    PASS 로 돌아선다.
[4] 32x32 from-S=4 wedge 는 in-flight 수(~4)로는 설명되지 않는다 — 별도 트레이스로
    판별하며, id 수정만으로 낫는다고 약속하지 않는다.

추가 등록 (floor-기본값 수정 후, 발사 전):
[5] 16x16 ms8 의 (0,3,0)/(3,3,0)/(2,1,0) 이 PASS 로 돌아선다 (tr=2 req 가 tr=4 로 올라가
    출력 창 토막이 사라짐). (2,2,0) 은 계속 PASS.
[6] 8x8 ms4 재격자: h=2 shape 의 ss_block_rows 가 2->4 로 바뀌므로 E536 의
    c(from S=4@h=2) = -1 이 **+1 로 이동**하면 "h<floor 보정" 은 sub-floor 기본값의
    아티팩트였고 S-규칙은 (+1,+3,+1) 로 통일된다. (사이클 자체도 달라질 수 있음 — 모형
    비교로 판단.)
[7] 32x32 ms4 (2,2,0) wedge 는 h>=8 이라 이 수정과 무관하게 남는다 (남으면 별도 추적).
[8] 검사기 w*t 확장으로 S=8 phase 의 상부 세그먼트가 처음으로 검사된다 — 여기서 새
    실패가 나올 수 있고, 그것은 회귀가 아니라 사각지대의 해소다.
