E491 사전등록 — 접기의 면적 비용은 배열이 커지면 어떻게 되나

여태 면적은 16x16 하나뿐이다 (+7.01% LUT, E481). 이 아이디어를 다른 데 쓸지 정하려면
비용이 크기에 따라 늘어나는지 줄어드는지를 알아야 한다.

기구를 세면:
  mesh(PE)        = rows * cols            -> O(n^2)
  스큐 망 mux     = rows * |shape 표|      -> O(n)
  gather/scatter  = cols * maxSeg          -> O(n)
  넓은 acc 쓰기   = cols * maxSeg          -> O(n)

접는 기구는 전부 **둘레**에 붙고 mesh 만 **넓이**로 큰다. 따라서 비율은 ~1/n 로 준다.
반대로 미는 힘이 하나 있다: ExecuteController 의 고정 제어 로직은 n 과 무관해서
작은 배열에서 분모를 키운다 — 8x8 의 비율을 예측보다 낮춘다.

측정: SSExecArea 를 8x8 과 32x32 에서 maxSeg=1 / maxSeg=4 로 OOC 합성.

[예측]
  [1] 비율은 크기에 대해 **단조 감소**한다.
  [2] 32x32 는 **5% 미만**, 8x8 은 **9% 초과**.  (16x16 = 7.01%)
  [3] 임계 경로 증가분(16x16 에서 +5.4%)은 크기에 거의 무관하다 —
      늘어난 것은 mux 한 단이고 그 깊이는 |shape 표| 로 정해지지 n 으로 정해지지 않는다.

틀리면: 비용이 넓이로 큰다는 뜻이고, 그러면 접기는 작은 배열 전용 기법이다.
