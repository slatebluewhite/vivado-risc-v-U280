E506 사전등록 — `max(h,4)` 의 4 는 누산기 WAW 해저드다. h=1 실패도 같은 것인가?

E505 까지 모든 분석이 `max(M,h,4)` 의 4 로 수렴했다. 그 4 의 출처를 찾았다 —
**upstream Gemmini 자신의 주석**이다 (ExecuteController.scala:363-370):

   "We can only retire one ROB instruction per cycle ... minimum floor of 2.
    Furthermore, **two writes to the same accumulator address must occur at least
    4 cycles apart** to allow the write to fully propagate through. Therefore, we
    raise the minimum floor for total_rows to 4.
    TODO: add a WAW check to the ROB so that we can lower the floor back to 2"

즉 4 는 systolic array 의 성질이 아니라 **누산기 쓰기 전파 지연(WAW)** 이고,
upstream 도 낮출 수 있다고 적어 뒀다.

**그런데 이것이 이 저널의 미해결 버그를 가리킨다.** E475~E477:
  'h=1 은 실패한다. 원인 미상. 두 기전을 배제하고 추적을 멈춘다.'
  E476: 'h=1 은 **chunk 가 둘 이상일 때만** 틀린다.'

chunk t>0 은 accumulate 비트를 켜고 **chunk t-1 과 같은 누산기 주소**에 쓴다.
그 두 쓰기 사이 간격이 곧 total_rows 다. 주석이 말하는 해저드와 정확히 같은 모양이고,
'chunk 가 둘 이상일 때만' 이라는 조건까지 일치한다.

[개입 실험] 바닥을 4 -> 16 으로 **올려서** h=1 이 고쳐지는지 본다.

[예측]
  [1] 바닥을 올리면 h=1 이 **통과한다**. 그러면 E477 의 '원인 미상' 이 닫히고,
      기전은 누산기 WAW 다.
  [2] 그래도 실패하면 WAW 가설이 **기각**되고, E477 의 판단(추적 중단)이 옳았다는 뜻이다.
  [3] 어느 쪽이든 h>=2 인 정상 shape 는 바닥과 무관하게 계속 통과해야 한다 (음성 대조).

**[1] 을 예측한다.** 조건 일치가 우연이라기엔 너무 구체적이다 —
주석이 'same accumulator address' 와 '4 cycles apart' 를 둘 다 명시하고,
E476 이 독립적으로 'chunk 둘 이상일 때만' 을 찾았다.
