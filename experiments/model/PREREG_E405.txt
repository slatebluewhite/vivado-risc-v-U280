사전 등록 — E405: Kc 방향이 뒤집히는 경계는 어디인가 (정사각 구간을 채운다)
작성 시각: kcdir3 이진을 만들기 전, 정사각 형상의 측정치가 존재하지 않는 시점.
판: rocket64b1gem3i8w256su20mem2f62, 블록 (8,8) 고정, m=3, 5회 재실행 칸별 최소.

## 지금까지 (E403/E404, 같은 판·같은 방식)

  가로로 긴 N/K=4 : 최선 Kc = 24(2청크) / 16(4청크) / 24(4청크)  <- **내부** 최솟값
                    [768x3072] [1024x4096] [1536x6144]
  세로로 긴 K/N=4 : 최선 Kc = 64 / 64 / 64  <- 전부 **상한**, 곡선이 상한까지 단조 하강
                    [3072x768] [4096x1024] [6144x1536]

N/K=1 구간은 비어 있다. E400 조항을 어디까지 적용할지가 여기서 갈린다.

## 두 읽기

H_ratio (종횡비가 변수):
    N/K >= 4면 내부 최솟값, K/N >= 4면 상한. 정사각은 그 사이이므로 **중간** —
    최선 Kc가 상한도 4청크도 아닌 어중간한 곳(3~4청크)에 오거나, 둘이 2% 안에서 비긴다.

H_N (큰 N이 해로운 원인):
    가로 무리에서 2청크 손해가 N에 따라 커졌다: N=3072에서 0%, 4096에서 +8.4%,
    6144에서 +10.0%. 원인이 **N 자체**라면 N <= 3072인 정사각은 세로 무리처럼
    **상한 Kc=64가 최선**이어야 한다.

## 예측 (등록)

**H_N을 지지한다.** 구체적으로:
  - [1536x1536] (N=1536): Kc=64가 최선. 4청크(Kc=24) 대비 **5% 이상** 빠르다.
  - [2048x2048] (N=2048): Kc=64가 최선.
  - [3072x3072] (N=3072): Kc=64가 최선이거나 4청크(Kc=48)와 **2% 안 동률**.
    ([768x3072]에서 N=3072가 정확히 동률이었으므로 여기가 경계일 것이다.)

빗나가는 방식과 그 뜻:
  - 정사각 셋 다 4청크가 5% 이상 이기면 H_N 기각, H_ratio 채택 -> 규칙은 종횡비로 쓴다.
  - 셋 다 2% 안 동률이면 둘 다 약하고, 이 구간은 "아무거나" -> 규칙을 단순하게 유지한다.

  성능은 보지 않는다 (CLAUDE.md: I*J가 한계일 때는 형상마다 검증하라).

  그러면 "청크는 공유할 때만"이 9개 형상으로 확인된다.
